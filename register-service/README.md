# register-service — the register.phext.io API

Backend for https://register.phext.io/ (v2). The page stays a static
file generated by `register-ui/generate_register_page.py`; this service
adds the stateful pieces behind the same origin at `/api/`:

- **Quick entry that actually lands** — `POST /api/entries` appends an
  atom `{type, text, user, ts, seq}` to an append-only JSONL log
  (`pending-entries.jsonl`). No more browser-local drafts.
- **Done buttons** — `POST /api/items/{n}/done` appends a resolution
  atom `{type, register_number, user, ts, seq}` to `resolutions.jsonl`.
  `{n}` is validated against `register-numbers.json` (emitted by the
  page generator beside `index.html`).
- **Auth** — LDAP password login (simple bind as the user against
  `uid=<uid>,ou=people,dc=mirrorborn,dc=us`, LDAPS to aletheia-core,
  house CA) and WebAuthn passkeys (RP `register.phext.io`), both
  fail-closed. Sessions are server-side records behind a signed,
  HttpOnly, Secure, SameSite=Lax cookie; state-changing calls need the
  session's CSRF token.

The service **never writes the register of record**
(`waiting-on-will.md`). Emise's progress ticks drain both logs via
`GET /api/entries/pending?after_seq=N` and `GET /api/resolutions`,
tracking the highest drained `seq` on her side; duplicate resolution
atoms for one number are recorded in the log and treated as no-ops at
drain time. Headless drains authenticate with a dedicated drain token
(`REGSVC_DRAIN_TOKEN`, sent as `X-Drain-Token`) that authorizes only
those two reads — never writes, never login.

## Layout

- `regsvc/` — the service (stdlib HTTP; deps: `ldap3`, `webauthn`).
- `tests/` — unit tests (mock LDAP/WebAuthn): 
  `python -m unittest discover -s tests` in a venv with
  `requirements.txt` installed.
- `deploy/` — systemd unit, env template, v2 nginx vhost, pinned
  `requirements.txt`, and `install-on-box.sh` (one-run install on
  awsbox; Will runs it with sudo).
- `ldap-ca.crt` — the Bickford House CA certificate (public) used to
  verify the LDAPS connection.

Config is via environment — see `deploy/register-service.env`.
The service binds `127.0.0.1:8791` only; nginx proxies `/api/`.
`python -m regsvc.server --selftest` performs a deliberately-failing
probe bind and exits 0 iff the directory refuses it (fail-closed).
